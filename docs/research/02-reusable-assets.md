## 2. RAG / askbot blueprint we already know works

“Works” here means an implemented prior pattern, with known defects identified below. No live CaseGPT deployment, paid inference run, or In Practise corpus was tested in this read-only review.

### Ingestion and corpus representation

CaseGPT accepts Markdown manuals, stores the raw body in `documents.content_md`, and explicitly invokes `index-manual` after upload. The edge function verifies the user and owner/admin role before creating a service-role client; it reads the document, parses sections, embeds them, and replaces its chunks (`C:supabase/functions/index-manual/index.ts:16-99`). The private `manuals` bucket and the document lifecycle (`active`, `draft`, `pending_parse`, `archived`) are in `C:supabase/migrations/20260424000002_chat_documents.sql:68-127`.

The chunker is **heading-based, not a fixed-token sliding window**. H1 supplies the manual title, H2/H3 delimit sections, an H2 preamble is attached to its first H3, and a single child H3 is collapsed. Empty sections are removed; each chunk has type, manual title, section path, ordinal, heading, Markdown, step count and estimated tokens. Types are `procedure`, `reference`, `faq`, `overview`. There is no overlap or enforced maximum chunk size in this path. Text before any H2 is ignored, so a heading-free document can yield zero chunks (`C:supabase/functions/index-manual/parseMarkdown.ts:4-72`, `C:supabase/functions/index-manual/mergeOnlyChildH3.ts:3-14`, `C:supabase/functions/index-manual/buildChunks.ts:9-27`, `C:supabase/functions/index-manual/classifyChunk.ts:5-17`).

Embeddings are direct OpenAI `text-embedding-3-small`, checked to be 1,536 dimensions; ingestion embeds sequentially. The initial schema used `gte-small`/384 dimensions, then a migration truncated old chunks and changed the column to `vector(1536)`. That destructive migration is historical evidence, not a safe reindex recipe (`C:supabase/functions/_shared/providers/openaiEmbed.ts:10-37`, `C:supabase/functions/index-manual/embedChunks.ts:5-12`, `C:supabase/migrations/20260425000002_pgvector_chunks.sql:1-24`, `C:supabase/migrations/20260425000003_embeddings_1536.sql:1-15`).

**Proposed adaptation:** retain public/synthetic source text with provenance URL, publication date, company/topic tags, document version and content hash. Preserve transcript speaker turns, headings and page/section locators. Normalize into Markdown before indexing, add bounded token splitting inside oversized sections, and record parser/embedding versions. Make indexing a durable job that builds a new revision and atomically activates it. CaseGPT's current delete-then-insert can leave a document without chunks on insertion failure (`C:supabase/functions/index-manual/persistChunks.ts:9-31`). PDF extraction is additional work, not an existing generic CaseGPT ingestion capability.

### Retrieval to answer

1. Authenticate with Supabase `auth.getUser`, enforce per-user request limits, validate the message and session ID, and verify ownership of an existing conversation. CaseGPT caps input at 4,000 characters (`C:supabase/functions/chat-completion/index.ts:43-145`).
2. Moderate input, resolve installation settings and user country/audience, and gate chat by feature flag. The planner classifies safety, topic shift, standalone query, up to two used variants, chunk-type priorities and answer mode; rules provide a fallback (`C:supabase/functions/chat-completion/index.ts:149-282`, `C:supabase/functions/chat-completion/planRetrieval.ts:18-72`).
3. Embed the original query, standalone rewrite and variants, with duplicates removed. Retrieve 30 candidates per branch through `match_chunks_hybrid_v4`. SQL unions a cosine candidate pool of twice the requested count with relevance-ranked FTS candidates, then ranks by cosine similarity plus a 0.10 keyword-match boost. It accepts country, audience, as-of date, type and FTS-language filters and runs with caller permissions. This is distinct from the next layer's rank fusion (`C:supabase/functions/chat-completion/index.ts:280-323`, `C:supabase/functions/chat-completion/retrieveChunks.ts:25-54`, `C:supabase/migrations/20260518000020_self_hosted_singleton.sql:319-396`).
4. Fuse branches with RRF (`k=60`), apply chunk-type priors, threshold and cap to 32; if empty, retry the original-query branch. Optionally rerank with Voyage `rerank-2.5` or Cohere `rerank-v3.5`, each with a 900 ms request timeout. A rerank failure falls back to the existing pool. Rerank text includes metadata and only the first 1,200 body characters (`C:supabase/functions/chat-completion/index.ts:325-370`, `C:supabase/functions/chat-completion/fuseRRF.ts:1-27`, `C:supabase/functions/chat-completion/applyRerank.ts:11-32`, `C:supabase/functions/_shared/providers/voyageRerank.ts:4-39`, `C:supabase/functions/_shared/providers/cohereRerank.ts:4-40`).
5. Choose six chunks with approximate MMR: normalized relevance weighted 0.7 and document/section duplication penalties. It is structural diversification, not pairwise embedding MMR (`C:supabase/functions/chat-completion/applyDiversityMMR.ts:1-49`). Generate using direct OpenAI, default `gpt-5-mini`, a structured response contract and 1,500 completion-token cap (`C:supabase/functions/chat-completion/index.ts:43-50`, `C:supabase/functions/chat-completion/index.ts:459-509`).

**Do not transplant the tuning blindly:** the fused score scale and threshold are incompatible, discussed in section 6. The broad fallback can mask the loss of multi-query fusion, especially with fewer branches or no strong type prior. ZeroHedge supplies a separate archived precedent for ClickHouse lexical/HNSW fusion, Redis embeddings and cross-encoder rerank, but its exact models, dimensions, fusion constants and corpus size are not established in the accessible evidence (`E:stories.md:499-512`).

### Citation, refusal and streaming contracts

The current structured assistant output is `{answerMd, source, confidence, guide}`. `confidence` is categorical: `answered`, `partial`, `not_found`, `conflict`; it is not a calibrated probability. `source` is a model-provided manual/section pair. Separately, the server derives source cards from retrieved document rows, deduplicated by document ID, using title, URL, `pdf|faq` type and section. Missing URLs become `#`; a `not_found` answer hides cards. Those cards establish retrieval provenance, not sentence-level evidence that every claim was supported (`C:supabase/functions/_shared/types/AssistantResponse.ts:1-10`, `C:supabase/functions/chat-completion/deriveSources.ts:10-37`, `C:supabase/functions/chat-completion/filterSourcesForConfidence.ts:4-12`).

The prompt treats retrieved text as untrusted reference data and requires refusal, partial answers or conflict reporting according to the fragments. It also contains retail-specific exclusions, including internal financial/business data: that policy would block the intended investment-research use case if copied unchanged (`C:supabase/functions/chat-completion/buildSystemPrompt.ts:45-65`, `C:supabase/functions/chat-completion/buildSystemPrompt.ts:104-119`). The parser currently accepts malformed prose as `answered`; strict JSON schema generation alone does not enforce abstention (`C:supabase/functions/chat-completion/parseAssistantResponse.ts:16-39`, `C:supabase/functions/chat-completion/parseAssistantResponse.ts:75-79`).

Guide mode now requires **at least three valid steps**, plus title, description, prerequisites, global warning and citation; the prompt asks for empty `answerMd` in guide mode. The older `CLAUDE.md` describes a two-step fenced-JSON extractor that is not the current implementation (`C:CLAUDE.md:27-35`, `C:supabase/functions/chat-completion/parseAssistantResponse.ts:82-105`, `C:supabase/functions/chat-completion/buildSystemPrompt.ts:71-92`). Reuse the stepper interaction for a research workflow only when source-backed sequential instructions add value; do not turn every research answer into a guide.

CaseGPT's browser wire protocol is **NDJSON, not SSE**: `delta` text records followed by a validated `final`, or an `error`. OpenAI streaming feeds an incremental `answerMd` extractor; structured metadata arrives at completion. The client handles split lines and an abort signal. Source cards open PDFs in the viewer or external links and record clicks. `MarkdownContent` now uses `react-markdown` + `remark-gfm` with `skipHtml`; `rehype-raw` remains in the manifest but is not enabled there (`C:supabase/functions/chat-completion/handleStreamingChat.ts:1-5`, `C:supabase/functions/chat-completion/handleStreamingChat.ts:37-137`, `C:src/services/chat-aui/streamChatMessage.ts:14-81`, `C:src/components/chat-aui/ChatAuiSourceCard.tsx:11-59`, `C:src/components/chat/MarkdownContent.tsx:1-14`).

**Proposed shared evidence contract for the UI and MCP:** an answer carries `answerId`, `conversationId`, `answerMd`, `status`, `citations[]`, `corpusVersion`, `traceId` and usage. Each citation carries an opaque `citationId`, `documentId`, immutable `revisionId`, `chunkId`, title, publication date, section/page locator, exact excerpt and an authorized application URL. Citation IDs in the answer must resolve to supplied evidence; validate excerpt membership and permissions on the server. No accessible evidence should produce a deterministic `not_found`, and partial/conflicting evidence should remain labeled. Render partial deltas as provisional until the final contract validates; an aborted or malformed stream must not look like a completed answer. These are additions, not fields already implemented in CaseGPT.

### Evaluation: useful scaffolding, incomplete quality gate

The checked-in golden set has **10 cases**, covering procedures, factual and definition queries, ambiguity, multi-turn follow-ups/topic shifts and out-of-scope questions. All ten `expectedChunkIds` arrays are empty. The harness records schema validity, confidence match, guide presence, manual/section match, recall@10, binary-relevance nDCG@5 and latency; missing expected IDs produce null retrieval metrics (`C:evals/golden.json:1-122`, `C:evals/scoreEvalCase.ts:14-50`, `C:evals/scoreRecallAt10.ts:1-13`, `C:evals/scoreNdcgAt5.ts:1-23`).

The current gate enforces schema pass rate >=0.95 and p95 <=8,000 ms; recall is disabled by default. It does not fail on confidence, guide, manual or section mismatch, despite calculating them. Baseline tolerance fields exist but the checker does not compare a baseline; `eval:baseline` sets an environment variable the runner does not consume. The “schema” check sees already-normalized output, so parser fallback can conceal malformed model JSON (`C:evals/getDefaultThresholds.ts:3-10`, `C:evals/checkEvalThresholds.ts:9-29`, `C:evals/run.ts:24-66`, `C:package.json:27-28`).

Multi-turn cases replay only earlier user messages and regenerate the assistant's earlier responses, introducing provider variability. Retrieval IDs come from `retrievalDebug.final`, which has at most six chunks, so the reported recall@10 is not measuring a ten-item candidate list. Without debug tracing it sees no IDs at all (`C:evals/runEvalCase.ts:9-55`, `C:supabase/functions/chat-completion/index.ts:47-50`, `C:supabase/functions/chat-completion/index.ts:372-374`).

**Proposed demo suite:** use stable revision/chunk identifiers and human-reviewed expected evidence; cover exact numbers, dates, speaker attribution, cross-document comparison, conflicting statements, missing evidence, prompt injection, forbidden content, revoked seats, cache boundaries, follow-up references and topic shifts. Score retrieval separately from answer faithfulness and citation correctness. Gate denied-content leakage and invented citations absolutely; choose quality and latency thresholds before measuring. Separate cold/warm caches, streaming/nonstreaming, errors and repeated stochastic runs. The 42-case Gemini moderation suite is a separate historical Shoutouts result, not CaseGPT's RAG evaluation or a demo score (`E:stories.md:41-49`).

The existing live `pnpm eval` command creates conversations, spends provider quota and writes `evals/results`; it was intentionally **not run** under this briefing's read-only rule (`C:evals/run.ts:20-56`, `C:evals/runEvalCase.ts:13-28`).

### What is evidenced

A “load-safety commit” is recorded, not evidence of a passing benchmark (`B:projects/zerohedge.md:54-59`). Do not borrow the historical 5/50/unlimited pitch tiers as a verified production policy (`E:stories.md:398-409`).

### Proposed minimal surface and shared service

Use one authorization-aware corpus service for REST, chat and MCP; transport adapters must not duplicate retrieval or bypass access checks. Expose only read tools:

| Proposed tool     | Input                                                                    | Output and behavior                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `search_research` | Query, optional company/topic/date filters, bounded limit, opaque cursor | Ranked excerpts and the shared citation records, `nextCursor`, corpus version. Never accept caller-supplied role or entitlement as authority. |
| `read_document`   | Opaque document ID, optional revision and section cursor                 | Authorized text sections and citations; check access again even if the ID came from an earlier search.                                        |
| `research_brief`  | Topic/company and date range                                             | Source-backed synthesis using the same answer/abstention contract as chat. No uncited market assertions.                                      |
| `my_usage`        | No user ID argument                                                      | Authenticated principal's counters, limits and reset times.                                                                                   |

Use deterministic ordering with an ID tiebreaker; bind cursors to query/filter hash, corpus revision and access scope. Reject stale or tampered cursors rather than returning mixed revisions. Cap response bytes and excerpts, not only result count. The prior scalable keyset-pagination lesson comes from Shoutouts directory sync, **not a verified ZeroHedge MCP pagination implementation** (`E:stories.md:179-189`).

For new code, the official TypeScript SDK documentation now identifies **v2** (`@modelcontextprotocol/server` and `@modelcontextprotocol/client`) as the stable line supporting the 2026-07-28 specification. Use matching v2 docs and a pinned compatible release; do not guess the archived server's dependency. [Official SDK](https://github.com/modelcontextprotocol/typescript-sdk).

Remote MCP auth should follow the current resource-server model: protected-resource metadata, authorization-server discovery, OAuth/PKCE, resource-bound access tokens and validation on each HTTP request. Keep server-to-provider credentials on the server; a transport session ID is not membership proof. Recheck active seat and scope before returning content. [MCP authorization specification, 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization).

Return schema-validated structured results and a compatible text representation where required by the negotiated protocol. Distinguish protocol failures from tool execution failures, and return bounded actionable errors without provider internals. Tool annotations describe read-only intent; server authorization must enforce it. [MCP tools specification, 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/server/tools).

Meter search/read/brief operations with atomic per-principal and organization counters, provider-concurrency caps and explicit retry/reset metadata. Do not silently bypass paid-access quotas if Redis is unavailable. Keep this distinct from the historical moderation availability tradeoff.

## 4. Members area blueprint

### Existing auth and data patterns

CaseGPT has password and email-OTP sign-in, auth-state subscriptions, persisted/auto-refreshed browser sessions, profile loading, language preference and sign-out. `RequireAuth` protects navigation; backend functions independently validate tokens. The intended role vocabulary is owner/admin/member, and the singleton setup promotes the first account to owner. The fresh-schema constraint defect is documented below (`C:src/features/auth/AuthProvider.tsx:15-98`, `C:src/lib/supabase/client.ts:10-16`, `C:src/features/auth/RequireAuth.tsx:12-33`, `C:supabase/migrations/20260518000020_self_hosted_singleton.sql:404-433`).

Conversations belong to `auth.users`; message policies check ownership through the parent session. Feedback has one upsertable positive/negative vote per message/user and an optional comment column. Settings includes MFA, data export and account deletion; those surfaces are useful product references, not proof that all privileged operations require MFA (`C:supabase/migrations/20260424000002_chat_documents.sql:14-66`, `C:supabase/migrations/20260426000001_chat_message_feedback.sql:4-27`, `C:src/services/chat-aui/saveFeedback.ts:10-25`, `C:src/pages/Settings.tsx:64-126`).

Invites are owner/admin-only and call Supabase's admin invite API with a server-configured redirect. There is no seat-cap check in that function. The singleton `tenants.plan` labels are not billing or entitlement enforcement; domain tables explicitly lose `tenant_id` in the simplification migration (`C:supabase/functions/invite-member/index.ts:27-57`, `C:supabase/migrations/20260518000020_self_hosted_singleton.sql:18-28`, `C:supabase/migrations/20260518000020_self_hosted_singleton.sql:233-260`).

The ATC principle transfers directly: filter role/language/audience **before retrieval reaches the model**; abstract the audience taxonomy (`B:projects/atc-portal.md:385-395`). Shoutouts' OIDC PKCE + Better Auth bridge used explicit Bearer tokens because cross-origin cookies were unreliable, with a deterministic reset on 401. Atmos mapped verified Staffbase identities into Supabase and separated external directory identity from application behavior. These are prior integration patterns, not reasons to add Staffbase or Better Auth to this demo (`B:projects/staffbase-shoutouts.md:168-190`, `B:projects/aa-atmos.md:60-76`).

### Proposed schema and policy for In Practise

The following entities are **new demo design**, not existing CaseGPT tables. Use one installation with many member organizations only if team seats are demonstrated; organization membership must be explicit rather than inferred from CaseGPT's singleton config.

| Entity                                                              | Minimum fields / invariant                                                                                                                                                                                        |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `profiles`                                                          | Auth user ID, display name, language; users can edit only these nonprivileged fields.                                                                                                                             |
| `organizations`, `memberships`                                      | Organization ID/name; unique `(organization_id,user_id)`, role, active/suspended state and seat activation timestamps. Separate member organization roles from platform staff permissions.                        |
| `invitations`                                                       | Organization, normalized email, requested role, expiring hashed token, inviter, accepted/revoked state. Reserve/consume a seat atomically; no silent first-organization selection.                                |
| `plans`, `subscriptions`, `entitlements`                            | Plan capabilities, seat limit, provider IDs, effective status/period, versioned feature/content grants. Maintain a server-side entitlement projection.                                                            |
| `documents`, `document_revisions`, `chunks`                         | Published/draft/archived state, public/synthetic origin, required access tier, dates and tags; immutable content/revision hash and evidence locators; chunks reference a revision.                                |
| `saved_items`, `workspaces`, `workspace_members`, `workspace_items` | Unique saved item per user/document; explicit private or organization sharing; permissions on both workspace and referenced content. Revoking premium access removes readable text, even if the bookmark remains. |
| `conversations`, `messages`, `feedback`                             | User/organization ownership; structured answer, citations, corpus revision and trace; feedback tied to a message the caller can access.                                                                           |
| `billing_events`, `audit_events`                                    | Unique provider event ID; processing state/retries; actor/action/target and timestamp for membership, publishing and permission changes. No credentials or entire private documents in audit payloads.            |

Public visitors receive only deliberately public summaries. Active members with an active seat may search/read/ask within their entitlements; organization admins may manage seats without gaining platform-editor powers. Platform editors can ingest and publish; platform admins can manage policies and evaluation settings. Every REST endpoint, MCP tool, storage download and citation read uses the same trusted principal and access predicate. A UI route guard is only navigation behavior. Supabase documents both service-role bypass and the need to make applicable views use caller RLS; review SQL functions, grants and storage policies as part of this boundary. [Supabase RLS guide](https://supabase.com/docs/guides/database/postgres/row-level-security).

For a Lovable SPA, reuse the Supabase browser-auth flow and validate tokens server-side. Keep privileged configuration server-owned; verify active membership on sensitive requests rather than trusting a stale role claim. If an HTTP-only backend session is introduced, specify CSRF and cookie policy as part of that change. MCP needs its own audience-bound authorization path tied to the same member identity, not a shared administrator token.

Billing should be simulated visibly for the synthetic demo unless an actual test-mode integration is requested. A future Stripe hook should verify event signatures, deduplicate event IDs and update subscription/entitlement state from authoritative events; handle failed renewal, cancellation and seat reduction rather than treating a checkout redirect as payment proof. ZeroHedge provides historical Stripe/Firebase integration evidence, not reusable CaseGPT billing code (`B:projects/zerohedge.md:83-91`). [Stripe subscription webhook guidance](https://docs.stripe.com/billing/subscriptions/webhooks).

### Proposed HTTP contract for the Lovable implementation

All endpoints below are a proposed `/api/v1` facade over the shared service. There is no claim these routes exist in a prior repository.

| Endpoint                                                                   | Contract                                                                                                                                    |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /me`                                                                  | Profile, explicit memberships, selected organization, capabilities and entitlement version; no secret fields.                               |
| `GET /documents`, `GET /documents/:id`                                     | Cursor/filter query; authorized summaries or authorized revision sections. Hidden IDs return the same not-found shape as missing IDs.       |
| `POST /search`                                                             | Query + bounded filters/cursor -> shared evidence results and corpus version.                                                               |
| `POST /conversations/:id/messages`                                         | Message + client request ID -> NDJSON delta/final/error records; creation handled by `POST /conversations`. Server owns identity and roles. |
| `PUT /saved-items/:documentId`, `DELETE /saved-items/:documentId`          | Idempotent save/remove after access check.                                                                                                  |
| `GET/POST /workspaces`, `POST /workspaces/:id/items`                       | Explicit ownership/sharing; require a selected workspace and authorized document.                                                           |
| `POST /messages/:id/feedback`                                              | Vote/comment on an accessible message, unique per caller.                                                                                   |
| `GET /admin/memberships`, `POST /admin/invitations`                        | Organization-admin scope, cursor pagination, atomic seat-limit check.                                                                       |
| `POST /admin/documents`, `POST /admin/documents/:id/index-jobs`            | Platform editor scope; document revision plus async job ID; repeat request IDs do not duplicate ingestion.                                  |
| `GET /admin/index-jobs/:id`, `GET /admin/corpus-health`                    | States/counts/failure reason/active revision, not fabricated progress.                                                                      |
| `GET /admin/conversations`, `GET /admin/feedback`, `POST /admin/eval-runs` | Explicit staff permission and audited access; eval run returns a job ID.                                                                    |
| `GET/PATCH /admin/settings`                                                | Validated flags/config with version conflict handling; credentials managed outside this payload.                                            |
| `POST /billing/webhooks/stripe`                                            | Provider-authenticated, idempotent event intake, only if the billing integration is added.                                                  |

Use a common `{error:{code,message,retryable},requestId}` response, 401 for unauthenticated, 403 for denied operations, 404 for unavailable objects, 409 for stale revisions/seat conflicts and 429 with retry metadata. A failed dependency returns a service error rather than `not_found`. This keeps Lovable's loading, empty, denied, expired and retry states distinct.

### Operations, cost and delivery

- **Cost and quotas:** CaseGPT enforces 20 requests/minute and 200/hour using fixed epoch-aligned windows, despite a migration comment calling them sliding windows; RPC errors fail open (`C:supabase/functions/_shared/rateLimit/CHAT_RATE_LIMITS.ts:1-4`, `C:supabase/migrations/20260519000001_rate_limit.sql:37-60`, `C:supabase/functions/_shared/rateLimit/enforceRateLimit.ts:30-39`). Generation cost is computed from a hardcoded table and final-answer usage, not total planner/embedding/reranker expense. Unknown pricing becomes null, and admin aggregation turns null into zero (`C:supabase/functions/_shared/cost/computeCostUsd.ts:9-42`, `C:supabase/functions/chat-completion/index.ts:555-572`, `C:src/features/admin-stats/api/getAdminStats.ts:31-43`). Record phase costs and unknowns, cap fan-out/concurrency and enforce an explicit demo budget; the constants are not current provider price quotes.
- **Availability choices are domain-specific:** Shoutouts intentionally failed open when moderation was unavailable and used retry/backoff and a separate billing project; CaseGPT's `omni-moderation-latest` call also fails open after errors/4-second timeout (`E:stories.md:41-49`, `C:supabase/functions/_shared/safety/checkOpenAiModeration.ts:21-63`). Preserve service availability where approved, but authentication, entitlements and ungrounded-answer refusal must not inherit that policy.
- **Truthful dashboards and exports:** admin message queries still run under the caller's session-owner RLS, so the tiles are not proven organization-wide totals. Queries ignore errors and sum an unpaginated result set (`C:src/features/admin-stats/api/getAdminStats.ts:16-43`, `C:supabase/migrations/20260518000020_self_hosted_singleton.sql:67-83`). The account export similarly assembles arrays without checking each query's error or paging (`C:supabase/functions/account-management/index.ts:41-75`). Build guarded aggregates and complete exports; errors must not masquerade as zero usage or complete data. Protect last-owner deletion in a future team model.
- **CORS and redirects:** preflight can echo the request origin, but static response headers select only the first allowed origin; additional allowed origins can therefore fail on the actual response (`C:supabase/functions/_shared/corsHeaders.ts:26-39`, `C:supabase/functions/chat-completion/handleStreamingChat.ts:56-63`). Carry request-specific headers through every response. Invites use server `APP_URL`, while browser OTP uses `VITE_APP_URL`; configure both and Supabase's redirect allowlist (`C:supabase/functions/invite-member/index.ts:17-18`, `C:src/features/auth/AuthProvider.tsx:80-85`, `C:docs/SMOKE-CHECKLIST.md:15-21`). Historical SMTP limits in the runbook should be rechecked against the selected provider rather than copied as current limits (`C:docs/runbooks/auth-down.md:19-30`).
- **Observability is not readiness:** the health endpoint checks configuration presence and a database request; it does not make an embedding/rerank/generation call or prove an active corpus exists (`C:supabase/functions/health/index.ts:13-40`). Langfuse receives raw user questions and parse failures can send response snippets to error telemetry (`C:supabase/functions/_shared/tracing/createLangfuseTurnTrace.ts:25-37`, `C:supabase/functions/chat-completion/index.ts:530-539`). Add synthetic canaries and redaction; retain trace IDs without exporting confidential text by default. Best-effort Sentry sends are unawaited (`C:supabase/functions/_shared/observability/captureServerException.ts:79-92`).
- **Durable background work:** Shoutouts lost in-process notification jobs on pod restarts and moved to Postgres + Cloud Tasks with deterministic task names and reconciliation. Its serverless hardening used `waitUntil`, bulk inserts and `p-limit` against 429s, with explicit tenant scoping because service credentials bypass RLS (`E:stories.md:149-156`, `B:projects/staffbase-shoutouts.md:205-225`). Reuse idempotent job semantics for ingestion and evals; a browser spinner is not job durability.
- **Directory scale and API drift:** Shoutouts fixed offset rescans with keyset pagination, bounded upserts and limited concurrency; concurrent full syncs could deadlock. A proposed API migration would turn inline group membership into N+1 reads and remained blocked (`E:stories.md:179-189`, `B:projects/staffbase-shoutouts.md:97-133`). Seats must derive from complete membership state, not a silently capped query or partially migrated API.
- **Synthetic data must be labeled:** CaseGPT's LCC scraper reads sitemaps and Playwright product pages, deduplicates URLs, bounds concurrency and supports dry-run/limit/reset, but per-product failures do not necessarily fail the whole run. It writes catalog rows, not research documents (`C:scripts/scrape-lcc-catalog.ts:35-115`, `C:scripts/scrape/runWithConcurrency.ts:18-32`). Physical-store counts and even online stock quantities are synthesized from a hash; only online availability informs them (`C:scripts/scrape/synthesizeStockByStore.ts:9-22`). Reuse pipeline boundaries, failure accounting and deterministic fixtures, never present generated counts as real inventory. Demo user creation is idempotent for existing emails but is still a privileged write (`C:scripts/seed/createDemoUser.ts:5-30`).
- **Secrets:** the archived Shoutouts notes record committed server keys/widget tokens and restriction without rotation; restriction did not remove historical exposure (`B:projects/staffbase-shoutouts.md:64-95`). ATC notes record committed service-account/SSO/storage keys already raised to its owners (`B:projects/atc-portal.md:374-383`). Some Brain pages themselves include credentials. None belongs in this report's demo assets, fixtures, browser config or generated project. These are recorded risks, not remediations performed here.
- **Deploys and migration history:** CaseGPT requires its Supabase wrapper to select the intended project; applied migrations must be followed by new migrations rather than edited. The README's old “migration repair” or no-op-comment rebundle advice is not a blanket safe remedy (`C:CLAUDE.md:5-23`, `C:README.md:225-236`, `C:README.md:312-318`). Reconcile actual schema/history and verify deployed artifacts before repair. The Lovable `bun.lock` registry trap is recorded; use the supported pnpm path (`C:CLAUDE.md:39-43`). Account-management deployment is in package scripts but absent from the smoke checklist's four-function list (`C:package.json:16-20`, `C:docs/SMOKE-CHECKLIST.md:7-13`).
- **Embedded UI and rollout:** Staffbase cookie/iframe, iOS Shadow DOM tap, progressive rendering and carousel-gesture issues were real host constraints, not generic React problems (`B:projects/staffbase-shoutouts.md:176-184`, `B:projects/staffbase-shoutouts.md:227-242`). Widget code upload and attribute registration were distinct; new attributes could still be stripped until registration synchronized. Versioned bundles enabled rollback (`B:projects/staffbase-widgets.md:38-51`, `B:projects/staffbase-widgets.md:88-103`). Use a standalone demo first and test any later embed in the actual host. The archived Gateway redirect annotation was inert without an HTTPRoute (`B:projects/staffbase-shoutouts.md:52-59`).
- **Product assumptions:** ATC's nominal manager role did not unlock manager analytics; healthy-looking dashboards had incorrect merged measures, and multilingual content was incomplete (`B:projects/atc-portal.md:57-90`). ContactMonkey's analytics API could not supply newsletter content; the implemented adapter used exported JSON/HTML and its real-account reimport remained unverified (`B:projects/atc-portal.md:148-173`). Never mark an integration delivered because an API exists.

## 7. What we would build differently in 2026

1. **One small shared corpus service, two consumers.** Keep Postgres/pgvector, authorization and immutable evidence together; REST/chat and MCP call the same service. Start from synthetic/public documents and an explicit provenance manifest.
